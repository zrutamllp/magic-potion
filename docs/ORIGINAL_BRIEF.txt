1. Executive Summary
This document outlines the project plan and technical architecture for a real-time, team-based collaborative web game. The game is designed for a corporate or educational setting, played by 10-20 teams simultaneously in virtual breakout rooms. It masterfully blends competition (which team finishes fastest with the most resources) with collaboration (all teams contribute to a single, overarching goal). The primary objective is to complete a series of tasks within a 90-minute time limit, managing resources and communicating effectively with other teams. The entire experience will be delivered through a dynamic web application, with a focus on real-time data synchronization to create a lively and engaging event.

2. Game Concept & Core Loop
Each team, represented by a single operator in a breakout room, joins a unique game session using a provided code.

Onboarding: Players are greeted with an introduction page and a brief instructional video explaining the rules, objectives, and the user interface.

Initial State: Upon starting, each team is allocated a fixed amount of starting "Funds" (in-game currency) and presented with 5 "Task Cards".

3 Unique Tasks: These are specific to each team, ensuring a varied experience.

2 Common Tasks: These are identical for all teams, creating shared challenges and opportunities for collaboration.

Gameplay: Teams work to solve the tasks. The nature of the tasks can be varied (e.g., logic puzzles, riddles, information retrieval).

Resource Management: Teams can spend their Funds to receive hints for difficult tasks. The cost of hints could increase with each request.

External Interaction: An in-game "Email" system will send teams opportunities. Responding correctly to these emails will award bonus Funds.

Winning Conditions: The primary goal is twofold:

Competitive: Be the team that completes all 5 tasks in the shortest amount of time with the maximum amount of Funds remaining.

Collaborative: Successfully completing all 5 tasks allows the team to contribute their "Magic Potion" share to the collective goal.

Game End: The game concludes when the 90-minute timer expires. A final results screen reveals the team rankings and the total completion percentage of the "Magic Potion".

3. Key Features
a. Real-Time Dashboard & Leaderboard
A persistent, live-updating dashboard will be visible to all teams throughout the game. It will display:

Team Standings: A list of all teams.

Task Progress: A visual indicator (e.g., 5 empty/filled stars) showing how many tasks each team has completed.

Funds Remaining: The current Fund balance for each team.

Magic Potion Meter: A large, central visual (e.g., a filling bottle or a progress bar) showing the collective progress towards the final goal. This meter updates in real-time whenever a team completes all their tasks.

b. Communication Hub
Global Chat Room: A single chat room, similar to a Slack channel, where all teams can communicate.

Strategic Limitation: Each team will be limited to sending only 5 outgoing messages for the entire game, making communication a valuable and strategic resource.

Fund Transfers: Within the chat or a separate interface, teams can send and request Funds from one another, fostering negotiation and alliances.

c. The "Magic Potion" - Collaborative Goal
The "Magic Potion" is the ultimate collaborative goal. The total potion is 100%. Each team's potential contribution is calculated based on the number of participating teams.

Formula: Contribution % = 100 / (Total Number of Teams)

Example: With 10 teams, each team holds a 10% share. With 20 teams, each holds a 5% share.

When a team completes its 5th and final task, its share is instantly added to the global potion meter, visible to everyone.

4. Recommended Technical Architecture (Self-Hosted on VPS)
To accommodate the need for a corporate-friendly, self-hosted solution on your Hostinger VPS, we will use a classic and powerful stack. This architecture provides full control over data and infrastructure.

Backend Runtime & Framework: Node.js with Express.js. This is a highly popular and robust combination for building the application's backend API. It will handle all game logic, such as validating task submissions, processing fund transfers, and serving data to the clients.

Database: PostgreSQL. A leading open-source object-relational database renowned for its reliability, data integrity, and performance. It is a standard choice for enterprise applications and will serve as the persistent storage for all game data (teams, tasks, progress, etc.). You will have full control over its installation and management on your VPS.

Real-Time Communication: Socket.IO. To replicate the live, dynamic updates (like the dashboard and chat), we will use the Socket.IO library. It enables real-time, bidirectional communication between the server (your Node.js app) and all connected clients (the players' browsers) using WebSockets. When a team completes a task, the server will use Socket.IO to instantly "push" the updated game state to every player.

Frontend Application: React.js. This remains the recommended choice for the frontend. Its component-based structure is ideal for building the complex, interactive UI of the game. It will communicate with your Express backend via standard API calls and a persistent Socket.IO connection.

team_tasks (Join Table)

status: VARCHAR(20) DEFAULT 'pending' -- (pending, complete)

PRIMARY KEY (team_id, task_id)

chat_messages table

text: TEXT
